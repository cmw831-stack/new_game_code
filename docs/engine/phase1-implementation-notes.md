# Phase 1 规则引擎：实现说明

**日期：2026-10-26**

**对应规则：** [主计划 V1.8](../design/wulin-self-created-arts-v1.8.md)、[战斗细则 V1.1](../design/wulin-combat-system-v1.1.md)、[组件细则 V1.1](../design/wulin-components-v1.1.md)、[敌人细则 V1.1](../design/wulin-enemies-v1.1.md)、[执行契约 V1.1](../design/wulin-phase1-contract-v1.1.md)。

## 一、现在有什么

| 部分 | 位置 | 内容 |
| --- | --- | --- |
| 规则类型 | `src/rules/types.ts` | 战斗状态、武学、敌人脚本、事件；全部是可 JSON 序列化的纯数据 |
| 随机数 | `src/rules/rng.ts` | mulberry32，只在套路段落交界抽取下一段落时使用 |
| 组件价表 | `src/content/components.ts` | 五槽组件、统一计价、兼容检查 |
| 内容目录 | `src/content/catalog.ts` | 十二门预设、三种卷首残页补法、敌方专用武学、三把兵器、引导与五类标准敌人 |
| 输入与校验 | `src/engine/setup.ts` | 构筑、资源、内容 ID 校验；非法输入在执行前报错 |
| 一轮结算 | `src/engine/round.ts` | 显示敌招 → 共同准备 → 轮初恢复 → 先手／后手基础行动及整根连锁 → 轮末 |

`runRound` 是纯函数：先复制状态再结算，所以同一函数也是“本轮预览”。

论艺配置、兵器特性、敌人词缀与历练题目尚未接入（按执行契约分别在后续阶段）。

## 二、怎么运行

```bash
npm install
```

```bash
npm run check
```

`check` 先做 TypeScript 类型检查，再用 Node 内置测试运行器跑 `test/` 下的全部测试。需要 Node 24 或更高版本，`.ts` 文件由 Node 直接执行，没有构建步骤。

## 三、验收测试

| 文件 | 覆盖 |
| --- | --- |
| `test/acceptance.test.ts` | 执行契约第四章全部案例：寒霜破势同根、留力、受击反震优先、两次接触、完全闪避、格挡仍能开招、同批回气再反击、破绽跨轮、冻结与架招、死亡与限次、安全上限、保存恢复一致、预览、非法构筑、决策不足 |
| `test/handcalc.test.ts` | 奖励经济细则 5.3 节四轮纸面算例（含逐轮账本）、教学细则 3.1 与 3.3 节、敌人细则 8.1 节刀客算例 |
| `test/segments.test.ts` | 段落抽取的确定性、抽取时点、冻结跳过时不顺延、固定段落不耗随机数 |
| `test/content.test.ts` | 十二门总价复算、残页价目、敌人配置容量、疾步与刀客的段落约束 |

所有预期值都来自策划文档里的手算，不由引擎输出反推。为确认测试不是空跑，做过两次故意改坏规则的检查：去掉格挡减半时 8 个测试失败；让攻击方的跨武学接招抢在受击方拆招之前时 2 个测试失败。

## 四、实现时的解释口径

策划文档没有写死、而实现必须选定的地方如下。若与设计意图不符，应先改文档再改代码。

| # | 问题 | 本实现的选择 |
| --- | --- | --- |
| 1 | 哪些武学“每轮最多一次” | 按战斗细则 9.2 节模板表：归息、通脉、蓄元、养元、踏风、回身、守拙。组件细则 1.2 节只写了“回气类内功”，两处说法不完全一致 |
| 2 | 连锁的实现方式 | 批次用显式循环；单门武学的结构（主招 → 受击方拆招 → 变化 → 收势）用有深度上限 16 的递归。递归有界，超限按安全上限终止 |
| 3 | 内力“向上跨过阈值” | 结算前低于阈值、结算后达到或超过阈值 |
| 4 | 已有技能护势时再架招 | 不叠层、不刷新，保留原护势 |
| 5 | 护势锁定 | 锁定到第一门出现未被闪避打击的敌方主招；即使本人本轮已崩溃无法格挡，也照样锁定，该主招结束后消费 |
| 6 | 破绽期限 | 记录制造者当前的基础行动序号 N，在第 N＋1 次基础行动机会及其整根连锁结束后过期；被冻结跳过的机会也算 |
| 7 | 冻结保护 | 跳过第 N 次机会后，第 N＋1 次机会受保护；寒意上限从冻结施加起降为 2，直到受保护行动的整根连锁结束 |
| 8 | 蓄震的目标 | 反击触发它的那门多段主招的出手方 |
| 9 | 变化子招的限次 | 与父武学分开计算根限次 |
| 10 | 敌方“禁用”主动武学 | 对整轮生效 |
| 11 | 段落抽取 | `mulberry32 值 % 段落数`；段落数很小，取模偏差可忽略，且结果确定 |
| 12 | 资源与伤害 | 全部为整数；格挡减半向下取整，崩溃恢复按上限的 40% 向下取整 |
| 13 | 实验室里“已取得的武学” | M3 十课教学与授业接入之前，构筑实验室暂时把先行六门全部视为已取得（`app/src/lab.ts` 的 `ACQUIRED_ART_IDS`）。检查本身按传入的已取得列表判定（`src/edit/loadout.ts`），接入授业后只换数据来源 |
| 14 | 构筑校验的顺序与范围 | 开打前逐项列出全部问题（武学位、未知、未取得、重复、剑专用、超容量），不在第一条就停；超容量时列出每门武学与兵器各占多少。开打时 `createBattle` 再校验一次 |
| 15 | 变招的“一项调整” | 一次变招只能是三者之一：本轮优先级（必须是已装备武学的完整重新排列）、暂停恰好一门已装备武学、本轮留力（非负整数）。不合法时整轮不结算、不扣次数。网页里与原编排相同的调整不提交，不白用一次 |
| 16 | 暂停的武学 | 本轮不进入候选，不记“没发动”；默认层由变招那一行说明 |
| 17 | 单槽替换为“无” | 劲力、变化、收势换成中性“无”不需要解锁，算一次替换（组件细则第九章的修正建议多次给出“设为无”） |
| 18 | 同一主招换档 | 例如连击乙→甲，按一个槽不同计，新档须已在全局组件库；与领悟的“切换整档”结果相同 |
| 19 | 改良版继承什么 | 名称类别、每轮限次沿用来源模板；来源带剑专用组件时，改良版记 `swordOnly`，换成通用主招也不解除 |
| 20 | 差异的比较对象 | 始终与来源预设模板比较；改良版不能再作为来源（组件细则 7.1 节“换名、复制和版本回退都不能绕过差异计数”） |
| 21 | 残页组件与全局组件库 | 补全残页是纯函数，不向组件库写入任何条目；组件库只由研究与授业记录生成（Q2） |
| 22 | 残页固定槽填同值 | 对固定槽填写与写定内容相同的值不算替换，不报错 |
| 23 | 秘籍 ID 与版本 ID | 秘籍 ID 为 `m` 加存档内递增序号；版本 ID 为 `秘籍ID@v版本号`，作为武学 ID 装备。名称只用于显示 |
| 24 | 名称长度与默认名 | 最多 16 个字（教学细则只写“长名提示调整”，未给上限）；空名时改良版默认“来源名·改”，残页秘籍默认残页名“折锋” |
| 25 | 导入时检查什么 | 结构、ID 一致与编号计数不对时整份拒绝；单个版本只重查装配形状与内容版本，失效时保留记录、不能装备。研究权限只在保存当时检查，导入不复查 |
| 26 | 实验室的改良权限 | M3 接入授业之前，按 `grant_edit_intro_v1` 的结果开放：断势击、叠寒剑精通，组件库只有破势甲与连击乙（`app/src/lab.ts` 的 `LAB_RESEARCH`）。因此目前可做的改良是两门主招互换档、或把可选槽设为“无” |
| 27 | 本地存档 | 浏览器 localStorage 的 `wulin-lab-archive-v1`；读不到或写失败时页面照常可用并提示，损坏的本地存档不被覆盖。导入会整份替换，先弹窗确认 |
| 28 | A／B 的决策序列 | B 照搬 A 本局的姿态与变招，不按 B 的状态另选；变招中的武学按装备位翻译，B 同位没有武学时该轮只做基础姿态。一方先结束后另一方继续按序列结算，直到序列用完 |
| 29 | A／B 的替换范围 | 网页里 B 只比 A 换一个装备位（任意已取得武学或已存版本），其余条件相同，保证分歧来源只有一处 |
| 30 | 没有机会发动的武学 | 默认层每轮最多加一行，列出本轮既没发动、也没有“未发动”记录的玩家武学：变招暂停、本轮已分胜负（对方已败退／自己败退）、对局中止，其余记为“起势未成立”并写出所需起势。插在结局行之前 |
| 31 | 词缀的应用顺序 | 先改上限（寒体气血、铁衣与身轻架势），再算开场资源（厚气内力、伤疲气血按改后上限的 70%）；重手在配置加成之后改基础出招。显式给出的开场气血优先于伤疲 |
| 32 | 寒体与冻结阈值参数 | 寒体在当场规则的冻结阈值上 +1（默认 3 → 4），保护期间上限为新阈值 −1（2 → 3），只作用于带词缀的敌人 |
| 33 | 伤疲的赏金补偿 | 实验室没有赏金，暂不实现“普通赏金按 2/3 发放”，Phase 3 接路线时补上 |
| 34 | 哪些配置不带词缀 | 引导配置与只循环开场段落的配置（教学检查点）在建立对局时拒绝词缀；路线首节点、论艺、具名课题由路线层负责不抽词缀 |
| 35 | 界面输入与可读性（教学细则第六章逐条） | 1/2/3 选姿态、Enter 确认、Esc 先取消已选姿态再取消待用变招；输入框聚焦时不触发；排序有拖动与上移／下移；重复按键或重复点击只承诺一轮；字号用 rem，跟随浏览器字号设置；词缀效果、预设说明、武学位已满等提示直接显示，不靠悬停；没有动画，“减少动态效果”与“跳过动画”目前不涉及；窄屏时三资源、意图、三个操作在战报之前；浅色主题小字的朱砂色调到 #a83c29（对比度 ≥ 4.5） |

## 五、调参实验用的开关

`BattleInput.rules` 与 `BattleInput.artOverrides` 只供调参实验使用，省略时就是 V1.8 规则与内容目录原值：

| 参数 | V1.9 默认（`DEFAULT_RULES`） | V1.8（`V18_RULES`） |
| --- | --- | --- |
| `rules.wardScope` | `chain`：基础架招护势保护敌方整条根连锁 | `main`：只保护第一门敌方主招 |
| `rules.initiative` | `enemyOnAttack`：敌方本轮意图为出招时敌方先手 | `player`：始终玩家先手 |
| `rules.freezeThreshold` | `3` | `3` |

`artOverrides` 覆盖目录武学的部分字段（双方共用），只用于实验与复现旧版本算例。每场开场内力上限 10（`OPENING_QI_CAP`）由路线层应用，`createBattle` 本身接受明确的开场内力输入，以便教学检查点与手算使用指定值。改默认值等于改规则，必须先改策划文档。

## 六、批量模拟

`src/sim/strategies.ts` 定义三套先行构筑与三份公开决策策略，`src/sim/matrix.ts` 运行 27 格矩阵与段落可行性检查。`npm run matrix` 按当前默认规则与内容生成 `docs/reports/phase1-matrix-<版本>-data.*`。V1.8 阶段的探索扫描与调参实验 1、2 的脚本已移到 `scripts/archive/`，它们依赖 V1.8 的默认值，复现时需检出对应提交。结论见 [模拟报告](../reports/phase1-matrix-report.md)、[实验 1 报告](../reports/phase1-experiment-1-report.md) 与 [实验 2 报告](../reports/phase1-experiment-2-report.md)。

## 七、Phase 1 还差什么

- 完成标准中的“在干净环境执行”：需要在另一台机器或干净目录按第二节复现一次。
- 模拟报告指出的数值问题需要负责人决定是否进入下一轮调参实验。
