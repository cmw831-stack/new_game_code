# Phase 1 规则引擎：实现说明

**日期：2026-10-26**

**对应规则：** [主计划 V1.8](../design/wulin-self-created-arts-v1.8.md)、[战斗细则 V1.1](../design/wulin-combat-system-v1.1.md)、[组件细则 V1.1](../design/wulin-components-v1.1.md)、[敌人细则 V1.1](../design/wulin-enemies-v1.1.md)、[执行契约 V1.1](../design/wulin-phase1-contract-v1.1.md)。

## 一、现在有什么

| 部分 | 位置 | 内容 |
| --- | --- | --- |
| 规则类型 | `src/rules/types.ts` | 战斗状态、武学、敌人脚本、事件；全部是可 JSON 序列化的纯数据 |
| 随机数 | `src/rules/rng.ts` | mulberry32，只在套路段落交界抽取下一段落时使用 |
| 组件价表 | `src/content/components.ts` | 五槽组件、统一计价、兼容检查 |
| 内容目录 | `src/content/catalog.ts` | 十二门预设、三种卷首残页补法、敌方专用武学、三把兵器、引导与五类标准敌人 |
| 输入与校验 | `src/engine/setup.ts` | 构筑、资源、内容 ID 校验；非法输入在执行前报错 |
| 一轮结算 | `src/engine/round.ts` | 显示敌招 → 共同准备 → 轮初恢复 → 先手／后手基础行动及整根连锁 → 轮末 |

`runRound` 是纯函数：先复制状态再结算，所以同一函数也是“本轮预览”。

论艺配置、兵器特性、敌人词缀与历练题目尚未接入（按执行契约分别在后续阶段）。

## 二、怎么运行

```bash
npm install
```

```bash
npm run check
```

`check` 先做 TypeScript 类型检查，再用 Node 内置测试运行器跑 `test/` 下的全部测试。需要 Node 24 或更高版本，`.ts` 文件由 Node 直接执行，没有构建步骤。

## 三、验收测试

| 文件 | 覆盖 |
| --- | --- |
| `test/acceptance.test.ts` | 执行契约第四章全部案例：寒霜破势同根、留力、受击反震优先、两次接触、完全闪避、格挡仍能开招、同批回气再反击、破绽跨轮、冻结与架招、死亡与限次、安全上限、保存恢复一致、预览、非法构筑、决策不足 |
| `test/handcalc.test.ts` | 奖励经济细则 5.3 节四轮纸面算例（含逐轮账本）、教学细则 3.1 与 3.3 节、敌人细则 8.1 节刀客算例 |
| `test/segments.test.ts` | 段落抽取的确定性、抽取时点、冻结跳过时不顺延、固定段落不耗随机数 |
| `test/content.test.ts` | 十二门总价复算、残页价目、敌人配置容量、疾步与刀客的段落约束 |

所有预期值都来自策划文档里的手算，不由引擎输出反推。为确认测试不是空跑，做过两次故意改坏规则的检查：去掉格挡减半时 8 个测试失败；让攻击方的跨武学接招抢在受击方拆招之前时 2 个测试失败。

## 四、实现时的解释口径

策划文档没有写死、而实现必须选定的地方如下。若与设计意图不符，应先改文档再改代码。

| # | 问题 | 本实现的选择 |
| --- | --- | --- |
| 1 | 哪些武学“每轮最多一次” | 按战斗细则 9.2 节模板表：归息、通脉、蓄元、养元、踏风、回身、守拙。组件细则 1.2 节只写了“回气类内功”，两处说法不完全一致 |
| 2 | 连锁的实现方式 | 批次用显式循环；单门武学的结构（主招 → 受击方拆招 → 变化 → 收势）用有深度上限 16 的递归。递归有界，超限按安全上限终止 |
| 3 | 内力“向上跨过阈值” | 结算前低于阈值、结算后达到或超过阈值 |
| 4 | 已有技能护势时再架招 | 不叠层、不刷新，保留原护势 |
| 5 | 护势锁定 | 锁定到第一门出现未被闪避打击的敌方主招；即使本人本轮已崩溃无法格挡，也照样锁定，该主招结束后消费 |
| 6 | 破绽期限 | 记录制造者当前的基础行动序号 N，在第 N＋1 次基础行动机会及其整根连锁结束后过期；被冻结跳过的机会也算 |
| 7 | 冻结保护 | 跳过第 N 次机会后，第 N＋1 次机会受保护；寒意上限从冻结施加起降为 2，直到受保护行动的整根连锁结束 |
| 8 | 蓄震的目标 | 反击触发它的那门多段主招的出手方 |
| 9 | 变化子招的限次 | 与父武学分开计算根限次 |
| 10 | 敌方“禁用”主动武学 | 对整轮生效 |
| 11 | 段落抽取 | `mulberry32 值 % 段落数`；段落数很小，取模偏差可忽略，且结果确定 |
| 12 | 资源与伤害 | 全部为整数；格挡减半向下取整，崩溃恢复按上限的 40% 向下取整 |
