## 评审结论与修订摘要

**V1.3 给出了系统框架，但装备、武学、成长和经济尚未形成完整的获取与消耗循环。V1.4 将这四项补成可核对的初始方案，仍需在原型中验证。**

| 本次补齐的内容 | 采用的方案 |
| --- | --- |
| 玩家穿戴与携带什么 | 四门武学、一把兵器、一件采集工具、两剂战间药；总容量 12，兵器特性也占预算 |
| 兵器如何成长 | 保障朴剑、轻剑、重剑同档，轻量省气但削势弱，配重多耗气但破势强；一剑一特性 |
| 武学从哪里取得 | 十二门完整武学具有固定教学／课题来源；完整武学、研究知识与自创版本分别保存 |
| 主角如何成长 | 从完整武功与基础连锁，进展到单槽改良、更多应对方式、五槽自创与实战验证 |
| 战斗能力是否无限叠加 | 首个 MVP 固定体能与共同容量，研究增加编辑与构筑选择，不重复购买永久攻击或生命 |
| 钱和材料花在哪里 | 银两用于补给、代配、制兵和返工，药材用于疗伤／人物病例／回气，矿材用于工艺 |
| 经济是否能算清 | 提供价格、配方、五节点收支、败退恢复与买入加工回售检查 |
| 开发是否立即扩大 | 实验室、医药切片、完整自创、矿冶依原阶段交付，不把全部经济塞进 Phase 1 |

战斗继续采用看敌招、选择攻守调息、武学自动接招与破绽兑现。长期保留知识、收藏、人物和已结算钱包；材料的仓库与未入库身份、败退扣半及不重复领奖继续有效。

本版提高了内容与成长的明确度，不能据此宣布整体数值、长期乐趣或商业可行性已经验证。下一步仍需补齐组件统一价目、首三类敌人的完整战斗配置、教学任务脚本与界面流程，形成首个实验室的执行规格。

## 第一章：项目定位与边界

### 1.1 游戏愿景

玩家扮演初入江湖的武者，在历练、采集、医治、锻造与结交人物的过程中，研究不同武学，逐步获得拆解与重组能力，最终创造能够被自己使用、被他人记住并传承的绝学。

核心体验是：**带着一个江湖问题出门，以技艺和自创武学提出解法，亲眼看到结果，带回新的知识、器物与关系，再改良自己的道路。**

核心宣传语保留：

> 习百家武学，悟万般变化。
>
> 不求天下第一秘籍，只创属于自己的绝世武功。

### 1.2 产品要求

1. 同一组件在不同构筑中有不同用途，不能只由数值高低决定选择。
2. 连锁反馈强烈，同时能让玩家解释关键触发、资源变化和中断原因。
3. 长期成长提供新的知识和选择，不依赖无限叠加基础属性。
4. 美术以 UI、静态角色、图标、声音和程序化特效为主。
5. 规则与内容结构化，支持自动化验证、批量模拟和 AI 辅助开发。
6. 生活技艺拥有可学习的知识、可选择的过程和可保留的成果；不同玩家可以侧重不同技艺，基本游玩不要求四项全部练满。
7. 人物与秘籍记得已经发生的事情，用少量持续关系支撑长期目标，避免每次历练重复同一段人生。

### 1.3 目标玩家与参考边界

面向喜欢构筑、自动触发、武侠成长、技艺探索和持续人物关系的玩家。V1.0 提到的《杀戮尖塔》《Path of Achra》《鬼谷八荒》《太吾绘卷》《Noita》用于讨论体验方向，不代表这些游戏的玩法可直接拼接，也不构成市场规模或商业回报的证据。

Roguelite 作为随机路线、临时收益和挑战变化的参考，不再要求整个人物或生活技艺每趟归零。具体产品定位以本版的“长期单角色养成＋随机历练”为准。

人物与武学当前采用功能占位名，世界设定、正式命名和内容来源由本作的叙事规划统一确定。

### 1.4 时间与联网方式

建议采用离线单机模式。战斗由本机规则引擎推进，正常暂停或关闭程序后不在后台继续战斗，重开恢复已保存的结算边界。核心玩法不要求常驻服务器、在线大模型或第三方游戏 API。

Steam 成就、云存档和其他平台能力属于本作后续发行规划。

## 第二章：长期成长、江湖历练与失败规则

### 2.1 每趟历练循环

据点整理 → 选择本次委托／研究目标 → 整备武学、兵器、工具与药品 → 沿路线战斗、采集或处理人物事件 → 改良与验证 → 继续深入或主动归来 → 入库、人物反馈与永久成长。

历练需要持续提供四类选择：

- **资源取舍：** 伤害、内力效率、架势防御和连锁稳定性之间如何分配。
- **针对选择：** 面对特定敌人，保留原构筑还是牺牲部分协同换取应对能力。
- **研究选择：** 推进已知武学，还是承担风险验证新的组合。
- **路线与生活选择：** 把有限节点机会用于采药、矿洞、医治或挑战；不要求每趟都兼顾所有系统。

### 2.2 据点与永久成长

回馆整理 → 学习武学与生活工艺 → 配药、锻造和研究 → 整理秘籍与兵器收藏 → 回访人物 → 选择下一趟目标。

永久成果包括武学知识与组件、自创秘籍、生活技艺与配方、仓库材料、收藏兵器、区域解锁、医案及人物进展。更丰富的知识和器物增加选择，但不设置可无限重复购买的永久攻击力／气血成长。

据点先以研究、医案、工艺和仓库界面表达，不加入建筑摆放、店铺经营、雇员、自动生产或现实时间等待。缺少材料时始终有免费基础休整、初始朴剑和基础路线可用，避免负债或伤病把角色锁死。

### 2.3 哪些保留，哪些随历练变化

| 项目 | 正常归来／主动撤退 | 历练败北 |
| --- | --- | --- |
| 已确认研究、技艺、配方和组件 | 全部保留 | 全部保留；未满足的挑战不自动完成 |
| 自创秘籍、收藏及出发携带兵器 | 全部保留 | 全部保留，不随机销毁永久兵器 |
| 人物阶段、已完成诊疗和已传授版本 | 保留实际已确认结果 | 保留实际已确认结果，不让已治好的人无故重新重伤 |
| 出发前留在仓库的材料 | 不受历练影响 | 不受历练影响 |
| 银两，含本趟已结算所得 | 保留实际余额，支出不回滚 | 保留实际余额，未获胜的战斗不虚发胜利赏金 |
| 已消耗药品与已支付费用 | 不退还 | 不退还 |
| 尚未使用的随身药品 | 归还剩余数量 | 归还剩余数量，不复制已消耗部分；携带总量仍受两剂限制 |
| 本趟未入库的可重复获取材料 | 带回入库 | 首轮提案：每种保留一半并向下取整；比例待试玩调整 |
| 唯一剧情证物、已确认委托成果 | 按任务状态保留 | 保留或提供明确恢复渠道，不造成主线锁死 |
| 临时战斗增益、路线状态和随机节点 | 结算后清除 | 结算后清除 |

失败通常表现为败退、被救回或提前结束行程，不以主角真实死亡后遗忘全部技艺解释。主动撤退在非战斗节点进行，会结束本趟后续机会，但可保全已经取得的材料；战斗中仍按战斗胜败规则处理，不能用关闭程序替代撤退。

知识不会因出行重置。每趟使用不同的携带配置、目标和临时机会，带来新的构筑问题。重新载入沿用同一历练／节点／战斗身份与随机状态，不刷新已经选择或结算的节点。

银两采用一份长期钱包，不再分银行与随身两套余额；每笔收入或支出在合法事件结算时记账。材料则明确区分仓库与本趟随身物资，不能用保存前的仓库快照覆盖已经发生的购买或制作。

### 2.4 区域与行程结构

保留初入江湖、门派纷争、宗师试炼三个长期区域层次。区域与主线进展永久解锁，每趟可选择已开放区域中的路线或跨区委托，不要求反复重演全部开场与人物相识。

路线先采用节点图，节点包含战斗、采集、休整、人物事件和明确的撤回机会。同一节点在本趟只结算一次，已取得的结果不能通过往返点击刷新。第一生活切片使用一条约 5 个节点的短路线，验证继续深入与带成果归来的取舍。

40–60 分钟一趟仍只是正式版行程假设；实验室与第一生活路线可以更短，时长由试玩校准。完整三区域、复杂旅行和经营均后置。

### 2.5 核心成功信号

失败后，玩家能够说出“这套功法的问题是什么”，主动修改并再次挑战；胜利后，也愿意尝试未经教程指定的组合。

自动播放出大量伤害数字只能证明表现有效，不能单独证明创造过程有趣。

新增观察：玩家会为了治好一个人、学会一种工艺或打造一把合适兵器而主动选择下一趟目标；已有成果能进入后续玩法，而非只作为收集数字。

### 2.6 玩家成长阶段

| 玩家阶段 | 可感知的成长 | 主要验证 |
| --- | --- | --- |
| 开场教学 | 拿到可用武功，理解出招、架招、调息与一次自动连锁 | 能解释发动与消耗 |
| 首次改良 | 一次性教学解锁一项合法替换，命名并保存改良版本 | 愿意改变招式再试 |
| 短路线与医案 | 取得更多武学，学会准备药品并帮助人物 | 成果与人物跨历练保持 |
| 进阶研究与工艺 | 选择不同起势、身法、回气与兵器方案，针对敌人取舍 | 多种构筑各有用途 |
| 化境与论艺 | 用已掌握组件完整组装，验证并选择传授 | 自创与版本具有实际价值 |

这些是玩家里程碑，开发 Phase 则是制作顺序，二者分别管理。具体来源、研究规则及体验时长假设见 [成长细则第二至四章](wulin-progression-economy-v1.0.md)。

## 第三章：武学结构、研究与编辑权限

### 3.1 五类武学

| 类别 | 主要用途 | 系统约束 |
| --- | --- | --- |
| 外功 | 攻击、削架势、制造破绽 | 使用统一伤害和命中规则 |
| 内功 | 内力循环、资源转换、持续支持 | 资源恢复也进入统一事件与触发限制 |
| 身法 | 闪避、起手与行动策略 | 不以渲染移动速度改变战斗结果 |
| 心法 | 事件响应、收益转换和反击 | 必须明确响应对象和触发上限 |
| 绝学 | 玩家创造的复合武学 | 使用同一套组件、容量、内力和兼容规则 |

分类用于理解和内容组织，不能成为绕过公共规则的例外入口。

### 3.2 五段组件契约

| 组件 | 职责 | 必须说明的信息 |
| --- | --- | --- |
| 起势 Trigger | 判断本门武学是否获得发动机会 | 监听谁的什么事件、条件、次数范围 |
| 主招 Action | 执行攻击、防御或资源动作 | 目标、打击次数、基础效果和基础消耗 |
| 劲力 Modifier | 修改兼容主招的效果 | 适用标签、逐击或整组作用、额外代价 |
| 变化 Follow-up | 在指定结果后追加变化 | 来源范围、是否产生新招、独立消耗和上限 |
| 收势 Recovery | 在声明的完成条件下结算后续收益 | 依赖主招还是追击、是否命中、结算次数 |

五段是武学的构成，不表示可以不看结果依次免费执行。没有满足起势、没有成功支付，或依赖的追击未命中，都不能自动取得对应收益。

### 3.3 四级研究权限

| 等级 | 能力 | 玩家学习目标 |
| --- | --- | --- |
| 初识 | 装备、基础排序并使用完整模板，查看主要触发链 | 认识武学的功能和成本 |
| 领悟 | 调整该武学设计允许范围内的参数，记录与比较结果 | 理解同一武学的时机差异 |
| 精通 | 在一个模板中替换一个已研究、兼容的组件 | 理解修改带来的收益与损失 |
| 化境 | 用已解锁组件进行五槽组装 | 在共同约束下创造新的武学结构 |

精通阶段保存的是“改良秘籍”，不能把一次单槽替换验收为完整自由自创。化境不包含任意编写脚本、自定义程序事件或无上限嵌套招式。基础装备排序、攻守调息与变招不被研究等级锁住；研究解锁的是这门武学的编辑权限。各级具体条件以 [成长细则第三章](wulin-progression-economy-v1.0.md) 为准。

### 3.4 拆解与兼容

研究不销毁原秘籍。玩家通过使用、观察、防御特定招式和研究挑战获得有限进度，解锁对应组件或原理。

组件需要具有明确标签和兼容条件。例如攻击型劲力不能直接附在纯回气动作上；要求剑类动作的变化，不能装入没有该标签的防御主招。

编辑界面应说明不兼容的具体原因，并尽量在装备前展示：发动条件、可能的连锁、内力收支、容量和触发次数。兼容预览不能声称能精确预测所有敌人和随机结果。

### 3.5 装备与容量

首轮平衡提案使用 4 个共用武学装备位。内功、身法、心法与自创绝学都占用装备位，避免出现不计成本的无限被动栏。

另设统一武学容量。首轮可从总容量 12 开始调优，模板与自创武学均按相同组件计价；强触发、低限制、多次发动和复杂追击应承担更高容量或资源代价。这个数值没有经过实测，不能直接视为平衡结论。

“自由组合”指在已解锁组件和统一规则内选择，不承诺所有槽位的任意组合都有效，也不把理论排列数量当作有效构筑数量。

出发时额外选择最多一把兵器、一件采集工具及两剂药品。兵器最多启用一条工艺特性；事件型或减耗特性占用同一个容量预算，并遵循统一事件、限次与成本下限。不能在武学已经用满容量后，再免费叠加一套装备被动。

采集工具先限采药包或矿镐，开启对应的专门采法／深入机会；每趟整备时选择，途中不通过反复免费换工具取得全部节点收益。不做工具耐久或挂机修理；未专精者仍可通过基础来源与购买获得常用材料。

首个采药包由教学提供，矿镐通过后续工艺教学取得，不要求先完成高级经济循环才有工具可用。

生活技艺不占四个武学装备位，也不按等级永久叠加战斗基础属性；它们通过配方、可选装备、路线和人物线索发挥作用。初期药品只在战间使用，不增加战斗内喝药动作或多套装备栏。

### 3.6 获取、掌握与自创分别成长

取得一门完整武学后可直接使用；掌握组件需完成该门的有限研究；自创秘籍引用已经解锁的组件并保存独立版本。改名、复制或返工不会重新发放研究与物品奖励。

十二门来源与一次性教学入口由 [获取表](wulin-progression-economy-v1.0.md) 管理。普通实验不增长永久研究，正式实战与有身份的研究挑战按各自上限记录。首个实验室只加载六门先行内容；完整 MVP 才投放全部十二门与四级研究曲线。

## 第四章：战斗时间、资源与结算规则

### 4.1 战斗形式与玩家选择

采用半自动短回合制、单人对单敌人。每轮敌人先锁定并显示意图，玩家再免费选择出招、架招或调息。选好后由规则引擎自动处理动作与连锁，也可开启简单自动策略，记录其真实选择。

每战暂有两次变招，在尚未承诺的一轮临时改变武学优先级、暂停一门可选武学，或修改追加攻击留力值，效果到轮末结束。基本姿态选择不消耗变招。变招不修改秘籍、不换装备、不回退已结算内容。

暂停、单步、快进与表现层无关，不改变行动机会、输入结果或收益。当前轮预览必须使用状态副本，不修改物品、研究或正式随机状态。

### 4.2 回合时序与基础行动

整轮采用：**展示已锁定敌招 → 玩家承诺输入 → 检查冻结并共同准备架招 → 双方轮初回气 → 先手基础行动及其整根连锁 → 后手基础行动及其整根连锁 → 状态到期、架势恢复与保存边界。**

首个原型玩家先手；如以后改变顺序必须提前显示。双方准备状态先提交，再按固定公开顺序结清准备连锁；轮初先各实际恢复 2 内力，再按固定公开顺序处理由此发生的响应。执行出招或调息前须再次检查最新冻结状态，不能只缓存轮初结果；已经完成的架招不回滚。任何阶段战斗结束都停止后续动作。

| 基础行动 | 首轮实验效果 | 行动限制 |
| --- | --- | --- |
| 出招 | 0 内力，气血威力 4／架势威力 4；合格时消费破绽使气血威力变为 6 | 占一次基础行动，保留资源不足时的可执行路径 |
| 架招 | 准备阶段恢复 4 架势至上限，建立本轮护势 | 准备即已使用基础行动，不再额外普通攻击 |
| 调息 | 行动窗口恢复 4 内力至上限 | 占一次基础行动，须承担对手本轮威胁 |

轮初回气与调息分别记账；实际增加为零不发送回气事件。气血／内力按实际结果延续到下一次遭遇，战间药品与有限休整提供补给，归馆有基础恢复退路。

### 4.3 三项资源与有限状态

气血为 0 立即败退；内力在发动前支付且不透支；架势承担压力，正数降到 0 时崩溃。破绽、护势、身法准备与寒意不增加常驻资源条。

护势最多一层，在下一门敌方主招首次出现未被闪避的打击时锁定为本招使用；击前仍有架势且本轮未崩溃时，气血伤害减半向下取整，架势伤害照常。该主招结束后消费护势，整招均闪避则不消费。导致崩溃的那一击仍按击前防御处理，后续击失去格挡。基础架招护势轮末到期；技能提供的护势／身法准备默认下一轮末到期，重复添加不叠层或刷新。

身法准备躲开下一次单独打击，消费后剩余连击照常；躲开的打击不造成接触伤害或寒意，也不消费护势。首轮不设常驻随机失误、随机闪避或随机暴击。

一方每轮最多崩溃一次，给予制造者一份破绽。第一项允许消费破绽的基础出招或指定重击／追击在实际接触时消费；普通多击不会无收益地消费，闪避不消费，不能叠加或刷新既有破绽。本轮未用的破绽保留至制造者下一次新实例基础行动及其整根连锁结束，不要求切换行动类型。下次架招在准备阶段结束窗口，冻结跳过该行动也不延长。崩溃者轮末架势恢复到至少上限的 40%（向下取整），不降低更高的当前值，也不因此清除破绽。

寒意正常上限为 3，达到阈值后清空并冻结，跳过下一次尚未使用的基础行动，不撤销轮初已经完成的架招。冻结不取消明示的被动拆招或反震。跳过后保留一个不会被同类冻结跳过的行动窗口；从冻结施加到保护窗口结束，寒意上限为 2，之后才可重新正常跨到 3。

先只实现少量状态，不把毒、血煞等候选流派同时放入首个实验室。

### 4.4 接触、支付与留力

默认基础攻击命中起势接受实际接触，包括被格挡的接触；完全闪避不触发。组件若要求未被格挡或实际气血损失，应明确显示并独立计价。只有实际扣血才产生受伤事件，实际回气才产生回气事件。

玩家可以设置追加攻击留力底线。自动主招攻击、反击或追击在付款后低于该值时跳过，不预支未来收势；防御与回气动作仍能使用保留的资源。跳过不扣费、不伪造完成或收势；已经支付但被闪避则不退款。

多击逐击记录实际结果，一击致死立即停止余下打击及未执行的收势。更多边界和四组手算以 [战斗细则第五至十一章](wulin-combat-system-v1.0.md) 为准。

## 第五章：统一事件与连锁约束

### 5.1 事件归属与信息

启用事件包括攻击开始／接触、实际受伤、闪避成功、格挡成功、架势崩溃、状态施加、实际回气、反击与武学完成，以及明确的边界事件。概率暴击事件随未来概率组件启用，不提前算作已完成内容。

事件至少携带来源与目标、基础／追加动作身份、武学及组件实例、实际效果、格挡／闪避结果、轮次阶段、根连锁、父事件和因果深度。事实为不可变记录，效果只能通过公共规则修改状态。

### 5.2 明确的拆招与接招窗口

1. 主招逐击提交伤害、崩溃与状态事实。
2. 主招结束后，先给受击方处理合法防御响应，按其编排检查回气、反震或反击。
3. 原出手者仍在场时，处理本门变化子招，独立付费与记录结果。
4. 对应结果满足条件才结算收势，再记录正常完成。
5. 将本门主招、变化、收势事实所产生的出手方其他武学候选合并，按编排排序继续接招。

子招也接受拆招；出手方跨武学候选合并到父招批次。若当前武学本身处于已锁定的响应批，新事实生成的己方候选先缓冲，原批处理完再构成下一批，不插队抢走原候选的资源；攻击引发的对方拆招窗口仍及时结清。变化不会自动继承父招完整五槽。自我回复不凭空创造被攻击窗口。使用显式工作队列与待决施放记录实现，不靠无界函数递归。

同一窗口内的候选按武学优先级、装备位、稳定规则 ID 排序；同规则匹配多条事实先合并。执行时再次检查目标、资源、留力和限次。付款失败后不因后来回气重扫旧事实，新的合法事实才可能给出新机会。

### 5.3 连锁约束与异常终止

一次基础行动或明确边界效果建立根连锁，双方的反击、变化和追击继承同一根 ID，不通过创建新根逃避预算。

同一角色、装备武学实例与组件规则默认每根最多成功自动发动一次；内功回气额外每轮一次。主招付款后内部的三击仍是完整三击，不被误当成三次自动发动。镜像双方额度独立。

诊断暂设每根 128 事件、每轮 512、每场 32,768、深度 16、每场最多 100 轮，全部是待测参数。超限停止未完成效果，已付费用不回滚，也不按正常胜利领奖。正常构筑频繁触顶应修订规则，不能靠提高预算掩盖循环。

### 5.4 三条优先验证的路线

| 路线 | 核心因果 | 主要代价 |
| --- | --- | --- |
| 寒霜连锁 | 基础接触 → 多击积寒 → 冻结／崩溃 → 追击 | 高内力消耗，多段攻击要面对反震 |
| 柔劲防反 | 提前架招 → 格挡 → 回气 → 反击 | 对手不出招时不能白得收益，要主动换姿态 |
| 破势爆发 | 基础出招 → 高架势伤害 → 崩溃 → 破绽重击 | 前期投入与兑现窗口需要配合，不能只堆即刻伤害 |

[战斗细则第九章](wulin-combat-system-v1.0.md) 给出十二门功能占位模板、八种主招、四种劲力及组合提案；完整组件价目仍须在编码前冻结，模板与自创不享有不同预算。

## 第六章：研究、顿悟与永久结算

### 6.1 有线索的研究

研究界面显示已知条件、已完成部分与下一条线索。初期通过教程让玩家先体验完整武功，再尝试一次收益与代价都明显的单槽替换。

连续格挡、低内力应对、低复杂度通关等可以作为顿悟条件，但应提供可追踪线索。未知奖励可以保留惊喜，条件不应全部依赖猜测。

### 6.2 实验室与永久收益分开

普通测试场可反复更换敌人与种子，使用已解锁组件试验，但不产生可刷的永久研究、奖励或冒险进度。

若需要在实验室教学解锁组件，应使用明确标记的一次性研究挑战，具有唯一挑战 ID 和结算记录。重播、重复胜利或读档不会再次给奖励。

正式历练中的使用与观察可提供有限研究进度。失败后保留已经结算的知识与研究，待结算观察随当前战斗状态保存，未满足的胜利挑战仍不发奖。生活事件可以提供线索或一次性研究机会，武学原理仍通过相应验证解锁，不由重复采集直接无限赠送。

### 6.3 结算幂等性

研究、奖励和挑战记录按唯一战斗／挑战 ID 结算。一次胜败结果最多提交一次，重放只供查看，不再次提交收益。

恢复同一场未完成战斗时沿用原战斗 ID，不能每次读档都创建一个新结算身份。实验室与冒险也在开始时明确来源类型，回放或展示不能将模拟结果转成冒险奖励。

局内结果与局外研究采用一致的存档提交机制，避免一个已经写入、另一个没有写入而导致重复奖励。战斗过程的临时预览不能直接改永久记录。

同一原则扩展到采集、制作、医治、传授和回馆入库：每项有唯一行为 ID，材料消耗、物品产出、人物状态与奖励一起提交。重载不能多得药品、重复扣材料，或在 NPC 已被治好后再次领取同一份信任奖励。

## 第七章：采药、医术、采矿与锻造

### 7.1 生活技艺的共同原则

四项技艺都是长期成长线，各自具有知识、操作选择和成果，不只提供一条被动加成。初期用节点事件、工艺选项和少量图标表达，不制作开放世界地形挖掘、挥锤动作模拟或全身经脉系统。

| 技艺 | 玩家选择 | 长期成果 | 与武学的联系 |
| --- | --- | --- | --- |
| 采药 | 辨认药材、选地点、决定是否深入 | 药材图鉴、采集知识、稀有产地线索 | 为疗伤和研究任务准备材料 |
| 医术 | 诊断、选择处理方法、配药与医治 | 药方、医案、独立处理病例的能力 | 通过救治与观察得到武学研究线索 |
| 采矿 | 勘察矿点、选浅层或深层、保全所得 | 矿材知识、矿洞路线与工艺线索 | 为不同兵器构型准备材料 |
| 锻造 | 选择材料、兵器形制与工艺 | 工艺配方、永久兵器收藏和改良版本 | 改变连击、内力与架势之间的取舍 |

生活技艺独立采用初学、熟练、精通三个有限阶段，与武学的四级研究权限分开。完整 MVP 先实现四种技艺的初学／熟练及可保存成果，精通内容后续扩展；不能只显示等级名称就计为已经交付。

| 技艺 | 初学阶段的可用能力 | 熟练阶段新增的实际选择 |
| --- | --- | --- |
| 采药 | 辨认前三种药材，使用普通采集点 | 辨识并选择第四药材归元叶分支 |
| 医术 | 教学掌握前两份药方，完成首个病例 | 独立配制已知配方的回气饮；未熟练者可购买或请人代配 |
| 采矿 | 认识基础矿材，选择浅层矿点 | 判断并选择公开新增战斗风险的深入矿点 |
| 锻造 | 在指导下完成轻重剑教学工艺 | 独立返工轻重结构，保存经验证的版本；未熟练者可请人代办 |

指导制作与独立掌握分别记录。首次委托可获得明确教学帮助，不制造必须先升到熟练才能完成初学任务的循环；熟练提供更自主的工艺或诊断选择。

晋阶来自识别新材料、掌握配方、解决新诊断、完成工艺验证和明确挑战。低级物品的重复采集与制作可以补充库存，但不会无限增加熟练度或永久战斗属性。

### 7.2 采药

采药点提供可观察的环境和药材线索。玩家在可靠的普通材料、较难取得的材料与继续赶路之间选择；已辨识知识保留，节点产出在本趟结算后不刷新。

不认识的材料可以记录、请教医师或购买已经鉴定的基础药材。采药知识提高可判断的信息和可用采法，不通过不断点击同一草丛无限升级。

第一生活切片只做青止草、续络藤、宁息花三种药材，支持止血散、续络膏两份配方；完整 MVP 再加入归元叶与回气饮。名称为游戏占位，配方、产量与实验效果见 [经济细则第五章](wulin-progression-economy-v1.0.md)。

### 7.3 医术、配药与医案

配药作为医术的一个分支，不额外拆出第五种生活职业。医术同时提供诊断、稳定伤势、制作用品和人物救治，不仅是免费回复按钮。

| 阶段方向 | 可获得的能力示例 |
| --- | --- |
| 初学 | 教学后自行制作前两份用品，处理首份病例，记录医案 |
| 熟练 | 独立配制已知回气饮，理解配方和耗材的适用性 |
| 精通，后续扩展 | 处理更复杂的配伍或武学伤身病例，获得新的研究机会 |

第一切片的两份配方分别用于战间疗伤和稳定剧情人物旧伤；完整 MVP 的第三份可用于战间恢复内力。毒与解毒配方等到相应状态机制开启后再加入，不提前铺开全部药理体系。

配药只在据点或明确的安全休整节点进行，消耗实际材料；野外只使用随身材料，不能远程调用仓库。初期每次制作一剂、每个休整节点提供一次制作机会，途中成品也受两剂携带上限约束。治疗自己先限战间，不能在战斗中任意插入喝药来逃避行动和内力成本。

允许把随身材料加工成至多两剂可保留用品，作为有限的物资保全策略；已经投入药品的材料从原料中扣除，败北时不再对它重复扣半。药品不会自动入库，返馆只归还实际未用的数量。

主角可带用品继续历练，也可归馆免费基础休整；归馆会结束本趟后续机会，因此野外医疗仍有价值。准备不足时有基础药品购买或医师指导，不要求玩家先练满医术才能正常出门。

医治 NPC 根据症状、许可、材料和阶段检查，未满足条件时给出原因，不扣材料或悄悄改变人物。完成后记录病例与人物状态；重复对同一已完成病例治疗不再增加信任或研究。首段病例不设置现实时间死亡倒计时，失败归来也不无故重置已稳定的伤势。

### 7.4 采矿

矿洞以路线节点表现。浅层采集侧重稳定回报，深入路线提供不同矿材并承担更多战斗或后续机会成本；不是在安全点无代价重复敲击。

第一阶段不增加饥饿、体力槽、矿镐耐久或现实采集等待。每趟节点机会、路线风险和携带工具形成取舍。熟悉矿材可获得更可靠的判断与替代材料方案，不直接叠加攻击力。

采矿在第二生活切片开放，先使用 3 种矿材和少量矿点事件。普通材料允许反复历练获得，稀有工艺来源与明确挑战关联，不靠一遍遍重载同一节点刷新。

一次性的工艺线索或配方永久保留；可能损失的耗材必须有可重复获取或替代来源。不能让一份唯一奖励材料丢失后，整条工艺线永久无法继续。

### 7.5 锻造与兵器收藏

初期锻造在据点进行，材料从仓库消耗；不加入移动熔炉或多层生产链。兵器来源限保障朴剑、据点制作、提供矿材代工、已开放成品购买及明确剧情赠与，不做大量随机词条掉落。

先提供朴剑、轻剑、重剑三种有限形制；朴剑作为可用的初始装备，轻重两种突出不同取舍。表中效果为方向示例，不是已测试数值。

| 兵器 | 唯一特性与代价 | 共同容量 |
| --- | --- | ---: |
| 朴剑 | 无额外特性，保留全部武学容量；保障配置不可交易或分解 | 0 |
| 轻剑 | 合格付费持械攻击内力减 1，最低 1；该次施放首个接触的架势威力减 2，最低 0 | 2 |
| 重剑 | 合格付费持械攻击内力加 1；该次施放首个接触的架势威力加 2 | 2 |

三剑的零费基础出招均维持气血 4／架势 4，兵器本体不额外免费加面板。修正按施放计算，不按每击重复；独立收费子招分别计算。先算最终费用再检查支付及留力。适用标签、算法与例子见 [装备细则第一章](wulin-progression-economy-v1.0.md)。

每把兵器最多激活一条工艺特性；先做两种互斥特性供选择，不叠加多套词条。减耗特性不能把原本收费的招式降到零；零费基础行动按原规则保留。事件型特性沿用统一事件与限次，并占用共同容量。

首版采用固定完整配置：朴剑无特性；轻剑的低耗收益与对应代价共同归入“轻量”特性，重剑的破势收益与对应代价归入“配重”特性。轻重效果不能作为免费形制收益再额外叠一条同类特性。两特性首轮各暂占 2 点共同容量，朴剑占 0，数值待验证；基础兵器数值保持同档预算，不通过改称形制绕过计价。

工艺成长开放可选结构与配方，不提供无限“强化＋1”。同品质兵器应存在用途差异；返工会替换指定特性并消耗材料，不保留上一条特性继续叠加。成品拥有稳定物品 ID 与版本，防止改良或重载复制。

永久收藏可以让玩家表达自己的路线。出发仍只能选择一把，未装备的收藏品不提供战斗被动。初期不引入强制修理和随机摧毁收藏兵器。

### 7.6 两条生活闭环

**采药医术：** 认识药材 → 准备配方 → 战间处理或医治人物 → 获得关系反馈与研究线索 → 通过武学验证解锁原理 → 改良自己的秘籍。

**采矿锻造：** 识矿与探路 → 带回材料 → 学习工艺 → 选择有取舍的兵器 → 调整原有武学配置 → 用实战验证工艺价值。

两者均不能替代核心武学创造，也不应成为出门前必须机械完成的日常。玩家可偏重某一技艺，借交易和人物帮助获得基本补给；专精的价值是更多自主处理方式和独特成果。

**首项工艺委托：同剑异用。** 由现有锻师发布，教学先提供本题所需的基础配方与工具。玩家带回可重复获取的矿材，在据点制作轻剑或重剑，按预先显示的续航或破势条件进行鉴定／试剑。消耗、产物与结果均真实记录，验证后一次性获得后续工艺线索。

作品由玩家收藏，锻师只鉴定作品和验证记录，不自动收走永久兵器。重复制造仍需材料，但不再领取同一委托奖励；奖励也不能反过来成为本题首次制作必需配方的唯一来源。两种工艺分别验证自己的优势，不能只把更高面板数值当作不同玩法。

### 7.7 物资、交易与重复收益

材料和银两属于持续世界资源，但武学容量、装备位、药品携带及同档兵器限制单次战力。MVP 不增加品质随机词条或强化等级；囤积普通材料可以减少准备压力，不能无限突破基础属性上限。新档一次获得 40 银两，后续购买、制作和收入均记真实余额。

基础材料与普通用品可购买，保障未专精玩家的基本可玩性。加工转售不应在同一商店形成无限无风险利润：普通回售价不高于对应零售投入，额外收益由有限需求的委托提供。

这里的零售投入按材料基准售价和明确工艺费用计算，不因本次材料是免费采来就把其出售价值算为零。采集成果仍可正常变现；限制的是没有路线、风险或需求约束的即时买进加工套利。

采集、制作、医治和交付都按唯一行为记录材料与结果；有明确身份的订单只结算一次。实验室中的试锻、试配或配方预览不消耗真实材料，也不产出可带走、出售或赠送的物品。

### 7.8 经济初始数据与验证

[经济细则第五至八章](wulin-progression-economy-v1.0.md) 给出四药材、三配方、三矿材、三兵器的固定价格与来源，以及五节点短路线的成功和败退账本。玩家可以自配、购买成品或提供材料请人代工，专精技艺提供自主选择。

一趟样例在起始 40 银两、买一剂止血散后，完成两场战斗取得 30 银两赏金，归来余额 48 并带回材料；若较难战斗败退，余额为 30，未入库材料扣半，已用药不退。这只是条件收支演算，没有证明战斗难度或用药量已经平衡。

重复历练收入允许积累。同据点即时买材、制作、回售不产生正利润；保障物品、一次性委托与研究奖励不能被反复领取。无需出门税、强制修理或医债维持消耗。MVP 的有限装备收齐后可形成余钱，长期正式版经济仍需后续内容和试玩评估。

## 第八章：轻量故事、人物关系与江湖记忆

### 8.1 一条持续目标

主角继承一份记满失败、旁注与空白的武学手稿。每次历练带回一个具体问题，例如剑法耗气过快、兵器不合手、伤势影响运劲，玩家用研究、医术与工艺留下自己的解法。

长期目标是补完一部自己能够使用、解释和传授的武学，在一次论艺试会中验证成果，并决定如何传承。开场不以获得现成最强神功代替创造过程。

第一生活切片只完成其中一页手稿和一段人物事件，提供闭合结果与后续线索，不宣称完整主线已经实现。

### 8.2 三位固定人物

人物当前使用功能称谓，姓名、背景、关系与武学传承将随本作的叙事规划统一设计。

| 人物 | 持续作用 | 与玩家成果的关联 |
| --- | --- | --- |
| 医师 | 指导诊断、药理与研究线索，提供基础帮助 | 认可实际完成的病例，讨论武学伤身和改良结果 |
| 青年剑客 | 求助者、共同研究对象及后续切磋对手 | 使用玩家愿意传授的改良版本，记得曾得到的帮助 |
| 锻师 | 鉴定材料与兵器，第二生活切片开放工艺 | 对比武器与武学的适配，认可经过实战验证的作品 |

三人以少量静态形象、短对话和事件反馈出现；师父可只作为手稿背景，不增加活动角色和演出成本。

人物信任由完成具体问题和选择推进，先采用清楚的阶段，不做反复送礼刷统一好感值。普通敌人模板与固定人物身份分别计数，不能靠换称谓充人物数量。

### 8.3 首条支线：续不上气的剑客

**起因：** 青年剑客旧伤未稳，原有剑法又过于耗气，希望继续参加试剑。

1. 医师指导玩家观察症状，确认要先稳定伤势，再验证剑法；准备不足时可先学习或求助。
2. 玩家选择短路线采药或购买基础材料，配制并使用病例所需用品，真实消耗材料，记录“伤势稳定”。
3. 交流揭示剑法的耗气问题，给予明确研究线索；治疗本身不直接赠送绝学或无限属性。
4. 玩家选择兼容的单槽改良，例如减少主招连击换取续航，或采用满足条件才回气的收势。
5. 在预先显示条件的试剑中验证：规定回合内有足够有效输出、存活并保有内力。纯防守不出招不能冒充改良成功，具体阈值待实测。
6. 玩家可记录自己的解法，并选择是否把该版本传授给剑客。愿意传授时，后续切磋确实使用受教时的秘籍版本。

病例试剑属于有唯一身份的一次性研究挑战，结算条件预先显示；它与可无限重复的普通模拟测试场分开。支线可跨两次或更多历练完成，不要求一趟内清空全部目标。

本题所需的可选组件在接取前或前段教学中已经解锁；试剑奖励后续研究与手稿成果，不能形成“先通过试剑才能获得通过本题所需组件”的前置循环。

医案按未接取、已诊断、伤势稳定、医案已结案保存，确认稳定处理成功后即可结案；武学课题另有研究已验证、手稿已记录等状态。是否传授以及受教版本属于独立可选标记，不作为医案结案或主线记录的必要条件。失败归来保留已确认阶段；未通过试剑不自动授予成功奖励。

救治与传授是不同选择：拒绝传武不会撤销已经完成的治疗。人物给予相应反馈，不强迫所有玩家公开自己最重视的秘籍。

玩家也可备齐材料或费用，请医师代为稳定伤势，继续人物与武学课题；代办不冒充玩家本人通过医术晋阶。这样故事不会强迫所有构筑都先练满医术。

### 8.4 让自创武学拥有履历

每门秘籍可记录首次创造、重要改良、真实挑战验证、帮助过的人和传授版本。履历绑定不可变版本和唯一事件 ID，不因读档重复记功。

NPC 学会的是受教时的版本。玩家以后修改自己的同名秘籍，不会隔空改变 NPC 已经学到的招式；更新传授属于另一个明确行为。

实验室成绩与正式江湖成果分开。模拟中击败一个敌人，不自动生成“救了某人”或“获得天下声望”的故事结果。

### 8.5 连续故事与随机历练共存

主线、人物状态与手稿进展持续保存，随机变化放在本趟路线、材料机会、挑战条件和临时收益。已经治好的角色不会每趟重新发同一病例；反复游玩时可改为请教、验证新版本、切磋或处理后续问题。

对话短、重复内容可跳过；保留医案与人物记录供回看。初期不做离线人物死亡、复杂 NPC 日程、伴侣系统、多人同行或大量分支演出。

## 第九章：自创秘籍、图鉴与存档

### 9.1 自创秘籍版本

每门自创秘籍拥有稳定 ID、玩家名称、来源模板／组件、版本号、兼容检查结果和研究要求。名称只负责展示，不承担身份识别。

修改后可另存一个版本，保留旧版。对比至少包括：实战伤害、内力支出与恢复、有效触发次数、存活轮次、造成的控制和架势贡献。不同敌人与种子的成绩分开显示。

“寒月归元剑”一类示例应能落实到真实组件关系：闪避获得发动机会，主招逐击积寒，达到冻结条件后追击，收势只在对应追击确实命中后回气；未追击或未命中不能按成功结算。

### 9.2 图鉴

记录完整武功、组件、研究进度、已知变化和曾经使用的构筑。生活部分分别记录药材／矿材图鉴、药方／工艺、医案、收藏兵器及关键人物反馈。原秘籍、组件解锁、自创版本和兵器成品是不同对象，不能因拆解研究就让原秘籍消失。

### 9.3 保存边界

建议同时保存：长期研究、四项生活技艺与配方、秘籍和兵器版本、仓库／银两、医案／人物阶段、受教版本、手稿履历、当前历练、携带配置、未入库材料、节点选择及随机数状态。

战斗快照至少包括双方气血／内力／架势、兵器与特性、状态与到期／剩余次数、冷却、已用变招次数、追加攻击留力值、敌方已锁定意图、双方基础姿态及是否已用行动、冻结保护窗口、仍有效的限次记录、轮次与下一阶段／行动方、已接受的决策输入、事件序号、原战斗 ID 和已结算奖励／研究 ID。

第一版先在回合边界保存，不承诺任意动画帧或半个事件中断都能继续。安全边界要求事件队列为空、没有待决变化或收势，且当前阶段标记明确；恢复不能把已经完成的轮初回气再执行一次。若以后支持事件中途保存，必须连同队列、施放依赖和待决输入一起适配，不能沿用当前边界存档的完成声明。

正常退出请求先停在安全边界完成保存，异常关闭恢复最近完整存档。奖励和研究不能因再次加载而重复发放。

生活行为和回馆也有各自的完整事务边界。保存已采集的节点、已用药品、材料消耗／产出及入库标记，退出再开不会重置采集机会、返还药品或重复执行失败损失。受教秘籍使用自己的不可变版本引用，不依赖玩家当前装备。

浏览器原型可采用 IndexedDB 等本地存储并保留导出能力的设计接口；PC 封装后使用相同数据契约对接本地文件。大批量回放日志需要保留策略，不能无限堆入小容量存储。

平衡更新后需重新检查旧秘籍。失效组件给出原因并保留原记录，不静默替换成另一门功法。旧回放缺少兼容规则或内容版本时明确说明不可重演，不能用新规则伪装成原结果。

## 第十章：敌人与长期可玩性

### 10.1 敌人检验策略，不只检验伤害

可保留 V1.0 的护架武僧、格挡剑客、毒师、低血爆发刀客和适应型宗师等长期候选。每种敌人应有明确行为、可观察线索和可理解的弱点，避免大量绝对免疫。

先行实验室只选三种行为差异明显的敌人：均衡武者、高架势守卫、蓄震守卫。完整 MVP 加入疾步剑客与蓄力刀客，分别检验身法消费和重击应对；这些是行为模板数量，不是五个换名、同比加血的单位。公开意图、反应代价及应对方式见 [战斗细则第十章](wulin-combat-system-v1.0.md)。

### 10.2 镜像挑战

镜像复用玩家武学的规则和组件，但拥有独立战斗状态、资源、触发额度和行为策略。它不能访问玩家隐藏决策或使用未说明的规则豁免。

镜像作为提高内容复用率的后续挑战。若基础敌人和自创规则尚未稳定，不与实验室第一阶段同时开发复杂自适应 AI。

青年剑客的受教后切磋先复用现有敌人规则与简单策略，只固定其受教构筑快照；这不等于已经完成独立镜像模式或自适应宗师 AI。

### 10.3 后期扩展

武林大会、固定容量挑战、随机武学限制、环境战斗、连续试炼与镜像挑战均可保留。加入新模式前，应确认现有构筑会因限制产生新的选择，而非仅要求更高伤害。

## 第十一章：界面、美术与反馈

### 11.1 表现方案

采用水墨方向的静态立绘或剪影、秘籍图标、简洁对峙画面及程序化剑气／掌风。优先投资 UI 可读性、攻击节奏、音效和关键连锁反馈。

建议第一版使用 DOM 界面配合 Canvas 2D 战斗表现。Three.js 可以在确有立体表现需求时另行评估，不作为核心原型的必需条件。

据点、采药、矿洞和工坊用节点图、少量静态场景、配方界面与工艺预览呈现。初期为 3 位固定人物准备可复用的肖像或剪影，不追加开放世界地图和大量劳作动画。

### 11.2 两层战斗记录

- 默认层展示武功名称、关键触发、资源变化、连锁总结果及未发动的主要原因。
- 详细层展开每个事件的来源、父事件、伤害、状态、次数和内力账本，用于理解和调试。

重复低价值提示合并展示，关键断点保留。例如“追击未发动：内力不足”应当能追溯到是哪门武学先使用了资源。

生活界面同时展示本次会消耗什么、得到什么、是否属于未入库物资，以及继续深入／归来的后果。诊疗说明实际已确认的症状和当前可用处理，工艺预览展示收益与代价，避免玩家只能盲目试错。

### 11.3 表现独立于规则

伤害数字、残影、停顿和震动只播放已经结算的结果。在相同决策输入下，改变播放速度不改变结果；关闭特效仍能理解与完成核心玩法。提供减弱震动和闪光的设置，状态使用文字／图标辅助区分。

## 第十二章：技术架构与 AI 辅助开发可行性

### 12.1 推荐原型技术

建议 TypeScript 独立规则核心、结构化内容、Web 界面和 Canvas 2D。构建工具可以选用 Vite 等成熟方案，先减少平台和渲染依赖。

核心不依赖浏览器动画帧、DOM、网络或在线 AI。运行输入包含规则／内容版本、武学与兵器构筑快照、敌人配置、种子和决策；输出包含结果、因果日志、资源账本与终止原因。生活与故事也以结构化规则和固定内容运行，不依赖在线生成对白。

### 12.2 模块职责

| 模块 | 单一职责 |
| --- | --- |
| 战斗核心 | 维护唯一战斗状态，处理资源、行动、状态和胜败 |
| 事件调度 | 候选响应、排序、归属、次数、队列与终止限制 |
| 武学编译与校验 | 将合法组件装配成统一规则，计算容量与消耗 |
| 研究系统 | 从已确认结果推进研究并幂等结算 |
| 历练系统 | 路线、节点、携带配置、未入库物资、撤回与失败结算 |
| 生活技艺 | 辨识、配方、诊疗、采集和工艺验证，不直接修改战斗队列 |
| 故事与人物 | 唯一事件、医案、信任阶段、手稿记录及受教版本 |
| 仓库与制作账本 | 材料、银两、药品与兵器归属，统一消耗／产出事务 |
| 存储与版本适配 | 保存、恢复、秘籍版本、兼容与迁移 |
| 表现层 | 播放结果、编辑构筑、解释因果及接收合法窗口内的决策 |

模块划分是职责边界，不需要第一阶段就做成多服务或庞大框架。事件系统与武学系统不能各自维护一份权威气血／内力。

仓库、随身物资和制作界面也共享一份权威库存。生活恢复与战斗事件分开，制作预览与真实产出分开；剧情不能绕过材料检查或直接把未验证的研究标为完成。

### 12.3 确定性与重放

同一个种子只有在相同规则、内容、构筑和决策下，才应重现同一结果。回放记录敌人意图、攻守调息选择、自动策略的实际输出、变招、留力与这些版本，并保留足够事件摘要用于查错。首轮基础攻击无随机命中骰子，种子主要用于可复现的敌人意图与路线选择。

伤害舍入、阈值比较、状态到期、同时候选排序和随机数消耗位置必须稳定。可优先使用整数或明确的定点规则，避免跨平台和将来跨语言时出现未定义差异。

同种子对比是理解改造的工具，不保证改变构筑后随机分支仍一一对应。平衡评估应使用一组预先固定的种子，结合不同敌人结果，而不是挑选单个有利样本。

### 12.4 必需的自动化检查

至少覆盖：

以下为检查目录；按当前阶段实际启用的机制实现，未启用的毒、血煞等扩展不因此提前进入 Phase 1，也不能记为已经通过。

- 同输入与版本的结果及关键事件序列一致。
- 己方／敌方归属正确，镜像双方的次数与资源独立。
- 内力不透支，资源上限、实际伤害和吸血记账正确。
- 多击、格挡、破防、阈值跨越和退场顺序正确；先后手都能轮初架招，且不额外赠送攻击。
- 防御拆招先于跨武学追击，破绽保留窗口、冻结保护与追加攻击留力正确。
- 同输入的本轮预览符合实际结果，预览不推进正式状态或发研究奖励。
- 无效起势、支付失败、未命中追击不产生错误收势。
- 净回气环、互相反击和预算耗尽均可终止并说明原因。
- 非法组件组合在战前被拒绝，合法模板与自创使用相同规则。
- 保存恢复保留构筑、随机状态与合法进度；奖励／研究不重复。
- 批量模拟可以记录胜率、轮次、内力效率、触发来源和异常终止比例。
- 采集节点不因重载刷新，制作消耗与产出一次提交，预览不能生成真实物品。
- 药品、工具和兵器携带上限有效，战间回复不触发战斗连锁。
- 正常归来、主动撤回及败北保留规则分别正确，损失不重复扣除，已用药品不返还。
- 已治愈／稳定的人物阶段、生活技艺和受教版本跨历练与重启保持，独立事件不重复领奖。
- 工艺特性计入共同预算，替换不叠加旧特性；减耗不把收费招式变成免费循环。

不要只根据引擎当前输出自动生成“正确答案”。关键测试向量需由规则契约推导，并人工复核少量可逐步解释的例子。

### 12.5 AI 辅助边界

AI 适合协助结构化数据、常规实现、回归测试、模拟工具、界面迭代与文档维护。规则冲突、体验取舍、平衡目标和真实玩家的乐趣仍需人来判断。

新增组件应说明事件、目标、成本、次数和兼容条件，并检查与现有机制的交互。不能把“数据驱动”理解为新增复杂规则不需要代码或测试成本。

### 12.6 PC／Steam 与 Unity 决策

原型通过后，优先进行一次小型桌面封装验证，再比较继续 Web 技术与迁移 Unity 的成本。验证离线启动、本地存档、窗口／全屏、输入、性能、安装及后续平台能力。

可复用的是规则说明、内容数据契约、测试用例和回放向量。TypeScript 引擎不能直接当作 Unity 的 C# 战斗代码，迁移必须重新实现或选择明确的运行桥接方案并重新验证。

Steam 接入、云存档冲突、成就和发行检查另列任务。本报告不将浏览器可运行等同为 Steam 可发行。

## 第十三章：MVP 范围、阶段与验证

### 13.1 三个交付层次

**先行武学实验室：** 在 Phase 2 交付，验证“愿不愿意改造再战”。保留 6 门预设武学、3 类敌人、攻守调息选择、单组件替换、命名保存、前后对比及因果记录。此时不要求生活系统或完整四级研究曲线已经完成。

**第一生活叙事切片：** 在 Phase 3 交付，验证“采药 → 配药／医治 → 改良试剑 → 人物反馈”。范围为 1 个据点、1 条短路线、3 位固定人物、3 种药材、2 份药方、1 个完整病例，沿用已完成的单槽编辑。至少跨两趟历练观察人物与成果的连续性。

**完整新版 MVP：** 在 Phase 6 交付，包含完整武学创造闭环、四项生活技艺、两条生活循环、有限携带与仓库、短故事及保存。第一生活切片不计为采矿锻造已经完成，武学实验室也不计为新版养成循环已经验证。

### 13.2 完整 MVP 的统一数量口径

| 模块 | 目标与口径 |
| --- | --- |
| 玩家 | 1 名可构筑角色，对单个敌人战斗 |
| 预设完整武功 | 共 12 门，包含 4 门内功；不是 12 加 4 |
| 主招组件 | 8 种可复用动作类型，与完整武功分别计数 |
| 起势组件 | 6 种明确的条件模板，不按参数变化重复计数 |
| 劲力组件 | 4 种；建议先选刚、柔、寒、震，毒与血煞留后续 |
| 敌人 | 5 种有实质行为差异的模板 |
| 研究 | 每门初识、领悟、精通、化境 4 级，有限记录与课题条件；基础战术操作始终开放 |
| 改良 | 精通阶段的合法单组件替换 |
| 自创 | 化境阶段的受限五槽组装，不包含脚本编程或无限嵌套 |
| 秘籍 | 命名、保存、编辑、版本对比与重新测试 |
| 战斗选择 | 每轮出招／架招／调息、可选自动策略、两次变招、优先级与追加攻击留力 |
| 战斗记录 | 本轮预览、因果链、资源账本、触发统计、终止原因和同输入重放 |
| 四项生活技艺 | 采药、医术、采矿、锻造均可学习、使用与保存，先实现初学／熟练两阶；精通后置 |
| 药材与药方 | 4 种药材、3 份配方，覆盖战间疗伤、人物旧伤和战间回气；解毒后置 |
| 矿材与锻造 | 3 种矿材，朴剑／轻剑／重剑 3 种同档形制、2 种互斥工艺特性；具体价格与返工账本 |
| 携带限制 | 4 个武学位、1 把兵器、1 件采集工具、2 剂药品；特性使用共同容量 |
| 经济 | 1 份银两钱包、固定买卖价、消耗／产出、一次性委托，失败与制作不套利 |
| 人物与据点 | 1 个据点、3 位固定人物、可复玩的短路线；不做经营和复杂日程 |
| 故事与委托 | 1 条完整医案支线、1 项工艺委托，以及明确的手稿进展；不是完整主线终局 |
| 人物反馈 | 治疗阶段跨历练保持，至少一次可选择的版本传授与受教后切磋 |
| 保存 | 研究、技艺、库存、装备、人物、受教版本、历练及战斗边界的一致恢复 |
| 挑战 | 少量连续遭遇、基础奖励与研究挑战；完整三区域及长期试炼后置 |

六种起势可先选择：自身基础攻击接触（含格挡）、自身闪避成功、自身格挡成功、敌方架势崩溃、自身内力向上跨阈值、目标状态向上跨阈值。受伤反击等可以后续扩展，不能因为事件已经存在就声称对应组件已经交付。

### 13.3 开发阶段与退出条件

本次不进入这些代码开发阶段，也不把上述表格改写为已完成进度。

本版继续保持原有内容规模，以装备、武学来源、有限成长与经济初值提高规则明确度，也增加相应数据与收支校验要求。Phase 2 之后先评估创造循环，Phase 3 之后再评估生活与故事是否增加有效目标；未通过时调整对应切片，不把四项生活系统同时堆进第一实验室。

### 13.4 三种有效构筑的操作性定义

在相同总容量、兵器品质、基础资源和解锁池下，三套构筑的主要伤害／生存来源应明显不同，而非只换名字或伤害属性。工艺特性占用总容量，药品准备条件一致；生活收益不作为偷偷放宽某套构筑测试条件的理由。

首轮调优可要求每套在至少两类敌人的 5 个预设种子中取得至少 3 次胜利，并至少出现一组“不同敌人下，构筑优劣排序交换”的结果。该门槛用于发现明显无效路线和万能解，不等于证明整体平衡。

### 13.5 真人试玩指标

| 指标 | 设计目标／观察方法 |
| --- | --- |
| 基本理解 | 目标 10 分钟内能说明敌招、攻守调息选择、一门武学的发动条件与主要成本 |
| 第一次改良 | 目标 20 分钟内完成合法单槽替换，并解释收益及损失 |
| 跨武学连锁 | 首次试玩中主动完成一条跨武学连锁，而非只观看教程自动播放 |
| 因果理解 | 玩家能指出一次关键触发和一次未发动的原因 |
| 跨轮决策 | 能说明至少两轮中的内力保留、攻守或击败时机取舍，避免只点即时伤害最高的按钮 |
| 自主实验 | 无人提示时，尝试教程之外的组件组合并查看结果 |
| 失败后的行为 | 能提出具体改造假设并再次挑战，而非仅重复点开始 |
| 完整创造 | 自由组装阶段能保存并重新使用一门非模板的合法秘籍 |
| 生活目标 | 玩家能主动提出采药治人、研究工艺或准备某种兵器的下一趟目标 |
| 有效取舍 | 能解释继续深入与归来、带药自用与救人、轻剑与重剑的至少一种代价 |
| 人物连续 | 记得帮助过谁，能发现对方在使用自己传授的具体版本 |
| 养成负担 | 观察是否出现“每趟都被迫先刷同一批材料”的乏味流程 |
| 长期成果 | 跨至少两趟历练确认秘籍、技艺、器物和关系留下可感知的变化 |

首轮可招募约 5 名不参与开发的玩家观察过程，保存每人的行为与问题。小样本用于找问题，不据此宣布留存率、长期可玩性或商业成功。自动化模拟通过不能替代这一环。

## 第十四章：风险、可行性与下一步建议

### 14.1 风险排序

| 风险 | 优先级 | 应对与判断信号 |
| --- | --- | --- |
| 连锁不可理解或结算自相矛盾 | 高 | 先冻结时序与归属，关键例子能手工推导 |
| 玩家只看动画，不愿改造 | 高 | 先做对比和因果反馈，观察自主修改与再战 |
| 循环与免费收益压过正常构筑 | 高 | 正常规则限次与资源代价优先，检查异常终止比例 |
| 内容很多但有效选择很少 | 高 | 不按排列数量论证深度，检验不同敌人的优势交换 |
| 研究能在实验室无成本刷完 | 高 | 普通模拟无永久收益，一次性挑战与冒险分开 |
| 永久收藏形成无成本万能构筑 | 高 | 固定容量与携带、工艺有代价，敌人和委托提出不同要求 |
| 生活技艺变成强制日常 | 高 | 以新知识和挑战晋阶，提供基础购买／指导途径，不要求四项全修 |
| 材料、治疗与制作循环无限套利 | 高 | 有限品质、回售价与委托规则，事务和唯一结算身份一致 |
| 每趟重置剧情破坏人物可信度 | 高 | 独立保存医案、已确认阶段、传授版本和后续反馈 |
| 编辑器比战斗本身更难用 | 中高 | 从完整模板与单槽改良进入，不先做复杂图形脚本编辑器 |
| 低美术表现缺乏吸引力 | 中 | 集中在清晰 UI、节奏、声音与关键剑气反馈 |
| Web 原型完成后迁移成本失控 | 中高 | 先验证玩法与桌面封装，再单独决定迁移 |
| 提前扩成大型江湖游戏 | 高 | 核心闭环未通过，不加入开放世界、经营、大量剧情和多人系统 |

### 14.2 开发可行性判断

规则模拟器和小型实验室适合 TypeScript 与 AI 辅助实现，前提是事件和组件语义先明确。新增生活与故事技术上可以复用节点、配方、事务与状态机，但确实增加库存经济、内容编写、交互和跨历练保存的工作，不能因为使用静态画面就把这部分成本忽略。

新版长期养成的乐趣、行程时长和 Steam 商业表现仍未知。本版不提供没有实际工作样本支持的完工日期或收入估计。先用 Phase 1／2 判断武学核心，再用 Phase 3 判断生活与人物是否增强动力，随后更新锻造与正式版的成本判断。

### 14.3 本次修订采用的方向与后续边界

本版已将以下方向纳入计划：

1. 同一主角长期成长，每次是一趟有独立风险与目标的历练。
2. 采药、医术、采矿、锻造都有可使用和可保存的成果，先医药再矿冶。
3. 以手稿、3 位固定人物和具体问题串联故事，人物不因新历练重置人生。
4. 兵器、药品和生活收益遵守共同战斗约束；普通实验不刷永久奖励。
5. 分别验证创造、生活与人物反馈，再扩展完整区域和长期挑战。
6. 每轮看招选择攻守调息，自创武学自动接招；拆招、留力与破绽时序采用独立战斗细则。

当前已补齐装备规则、武学来源与成长方案、配方和价格初值。组件统一价目及合法替换清单、首批敌人完整配置、逐步教学脚本与界面状态仍要在对应阶段落实；人物正式来源与命名、平衡和发行方案也需继续验证。若之后决定开工，将本版转成独立项目 GOAL 与分期验收，以本作独立的范围和验收标准管理。当前授权仍是策划完善，没有开始游戏代码开发。

**最终目标：让玩家因创造武学而想再试一场，也因学会技艺、留下器物和被人物记住而愿意再次归来。**
