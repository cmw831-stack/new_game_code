## 一、Phase 2 要回答的问题

**玩家输掉一场之后，愿不愿意改一处武学再打一次？**

这是主计划 13.1 节给“先行武学实验室”定的验证目标，也是第一次能让真人试玩的版本。Phase 2 结束时，你和约 5 位不参与开发的朋友应该能在浏览器里打开它、玩 30 分钟，并回答主计划 13.5 节的这些问题：

| 指标 | 目标 |
| --- | --- |
| 基本理解 | 10 分钟内能说明敌招、出招／架招／调息的区别、一门武学的发动条件与主要成本 |
| 第一次改良 | 20 分钟内完成一次合法单槽替换，并说出收益与损失 |
| 第一次创造 | 30 分钟内补全卷首残页、命名保存，并说出所选劲力的一项收益与一项代价 |
| 因果理解 | 能指出一次关键触发和一次“没发动”的原因 |
| 跨轮决策 | 能说明至少两轮中的内力保留或攻守取舍 |
| 失败后的行为 | 能提出一个具体的改造假设并再打一次，而不是只按“重来” |

Phase 2 **不**回答“生活技艺好不好玩”“长期养成有没有动力”，那是 Phase 3 以后的事。

## 二、范围

### 2.1 做什么

| 类别 | 内容 |
| --- | --- |
| 武学 | 先行六门：叠寒剑、断势击、崩势追击、归息诀、踏风步、借力诀；卷首残页·折锋 |
| 敌人 | 均衡武者、高架势守卫、蓄震守卫（标准配置，含段落 A／B），引导配置；首批 6 个公开词缀 |
| 战斗 | 每轮看敌人意图（含当前段落、本段剩余意图、下一段落）；选择出招／架招／调息；本轮预览；自动策略；每场两次变招；留力；武学优先级 |
| 因果 | 默认层：谁出手、哪门武学接上、谁花了内力、为什么没发动；详细层：完整事件、根连锁、资源账本 |
| 构筑 | 四个武学位、容量 12、铁剑；预设三套构筑；自由组合（只用已取得的武学） |
| 改良 | 叠寒剑、断势击由教学授予精通后，可做一次合法的单槽替换；卷首残页补全劲力槽；命名、保存为不可变版本 |
| 对照 | 同一对手、同一种子、同一决策序列下，A／B 两个版本并列对比（教学细则 3.1 节） |
| 教学 | 教学细则第三章的十课，按 V1.9 规则重新走查后实现；未完成的课可以随时免费补做 |
| 保存 | 实验版本、已取得的武学与授业记录存在浏览器本地；可导出、导入 JSON |
| 试玩支持 | 一键导出本次试玩记录（决策、结果、改良历史），方便我分析 |

### 2.2 不做什么

| 不做 | 原因 |
| --- | --- |
| 其余六门武学、疾步剑客、蓄力刀客、论艺配置 | 主计划把它们放在 Phase 4–6 |
| 研究证据点、化境、立篇、早期残页 | 属于 Phase 4 |
| 采药、医术、路线、钱包、人物 | 属于 Phase 3 |
| 兵器特性（只有铁剑）、历练题目 | 分别属于 Phase 5、Phase 3 |
| 正式美术、音效、动画 | 先用文字、图标和简单的水墨风格界面；表现层不影响规则 |
| 账号、云存档、多人 | 单机网页即可 |

## 三、玩家流程

```
实验室首页 ──┬── 课程（十课，按顺序解锁，可随时补做）
             │
             ├── 构筑：选武学、排优先级、设留力、看容量
             │      └── 改良：单槽替换／补全残页 → 命名 → 保存版本
             │
             └── 对局：选对手（三类标准敌人、引导配置，可选词缀）
                    ├── 每轮：看意图 → 预览三种姿态 → 选择 → 看结算与因果
                    └── 结束：胜负、关键原因、最多两条可试方向
                           └── 再战／改良／A／B 对照
```

界面以教学细则第四章的文字线框为准。键盘可以完整操作：`1`／`2`／`3` 选姿态，`Enter` 确认，`Esc` 返回。

## 四、技术方案

### 4.1 选型

| 部分 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | Vite | 策划书 12.1 节已选定；开发时即时刷新，产物是纯静态文件 |
| 界面 | **Preact**（React 写法，约 4 KB） | 界面里有大量列表、表单和状态，用组件框架比手写 DOM 更好维护；比 React 小得多，写法相同 |
| 语言 | TypeScript，沿用现有严格设置 | 与规则引擎共用类型 |
| 规则 | 直接引用现有 `src/` 引擎 | 引擎不依赖 Node API，浏览器可直接运行；网页和测试跑的是同一份规则 |
| 存档 | 浏览器本地存储＋JSON 导出／导入 | Phase 2 只有实验版本，没有正式进度 |
| 表现 | DOM＋CSS；Canvas 2D 留到第四个里程碑再评估 | 先把可读性做好 |

### 4.2 目录

```
src/            规则引擎（现有，继续保持纯函数、无界面依赖）
  edit/         新增：单槽替换、残页补全的合法性检查与版本模型
  narrate/      新增：把事件翻译成默认层／详细层的中文说明
app/            新增：Vite 网页（Preact 组件、页面、样式、本地存档）
test/           规则测试（node:test）
```

新增的 `edit/` 和 `narrate/` 放在 `src/` 里，是因为它们只是“规则→数据”的转换，可以用现有测试框架覆盖；`app/` 只负责显示和输入。

### 4.3 引擎需要补的部分

| 缺口 | 说明 | 依据 |
| --- | --- | --- |
| 敌人词缀 | 6 个词缀只改公开参数：气血上限、开场资源与状态、冻结阈值、基础出招威力 | 敌人细则 V1.2 第九章 |
| 单槽替换规则 | 来源模板已精通；新组件已解锁且兼容；与来源模板只差一槽；剑专用限制继承；重新计价 | 组件细则 V1.2 7.1、第九章 |
| 秘籍版本 | 稳定 ID、名称、版本号、来源（模板或残页）、五槽装配；保存后不可变 | 主计划 9.1 节 |
| 因果说明 | 停招原因要区分：内力不足、低于留力、起势未成立、状态已存在、次数已用、目标已败退、安全上限 | 教学细则 4.4 节 |
| 课程判定 | 每课按实际事实判定完成，例如“实际格挡一次”“实际造成崩溃”；授业只结算一次 | 教学细则第二、三章 |

### 4.4 测试

- 规则、单槽替换、残页、词缀、因果说明：继续用 `node:test`，预期值来自文档手算。
- 课程判定：每一课写一个“按推荐操作能完成”和一个“不按推荐操作也不会卡死”的测试。
- 网页：每个里程碑结束时，我用内置浏览器走一遍主要流程并截图核对；不额外引入浏览器测试框架。
- 新增 GitHub Actions：每次推送自动运行 `npm run check`。这同时满足 Phase 1 尚未完成的“在干净环境执行”。

## 五、里程碑

| 里程碑 | 内容 | 完成标准 |
| --- | --- | --- |
| M0 自动检查 | GitHub Actions 运行类型检查与全部测试 | 推送后在干净环境通过 |
| M1 能打一场 | 网页骨架；选预设构筑与对手；逐轮意图、预览、选择、结算；默认层因果；结果页 | 你能在浏览器里用三套预设构筑各打完一场，并看懂每轮发生了什么 |
| M2 改良与对照 | 自由组合；优先级、留力、变招；单槽替换；卷首残页；版本保存；A／B 对照；详细层因果 | 从输掉一场到改一处、保存、对照、再战，全程不离开网页 |
| M3 十课教学 | 按 V1.9 重新走查教学细则第三章并实现；授业与补课；首次进入的引导 | 新玩家不看文档也能从第一课走到第一次出门前的状态 |
| M4 试玩版 | 词缀；键盘与无障碍检查；水墨风格界面；试玩记录导出；发布试玩链接 | 5 位试玩者可以独立打开并完成 30 分钟流程 |

每个里程碑结束时我会：提交并推送（经你同意）、附截图说明能做什么、列出已知问题。M1 之后你就可以开始自己试玩并反馈。

## 六、风险

| 风险 | 应对 |
| --- | --- |
| V1.9 的数值只是模拟结果，真人可能觉得太难或太简单 | 这正是 Phase 2 要发现的；数值都在内容目录里，改起来快，并会重跑矩阵对照 |
| 教学课在 V1.9 规则下可能无法按设计完成（例如敌方先手改变首战） | M3 先逐课走查，做不到的课修改配置，不暗中给玩家加属性 |
| 因果说明太长，玩家看不进去 | 默认层每轮只保留能解释结果的几行；详细层按需展开 |
| 界面工作量超过预期 | M1 先做最少可玩；M2–M4 按价值排序，必要时把 A／B 对照或词缀后移 |

## 七、需要你决定

| 编号 | 问题 | 推荐 |
| --- | --- | --- |
| P1 | 界面框架：Preact、React，还是不用框架 | **Preact**：写法与 React 相同，体积小，组件化便于维护 |
| P2 | 试玩版怎么发给朋友：Claude 私有网页链接（Artifact），还是 GitHub Pages | **Claude 私有网页链接**：默认只有你能看，你决定分享给谁；不需要把仓库设为公开。GitHub Pages 需要公开仓库或付费账户 |
| P3 | 十课教学放在 Phase 2，还是先只做前三课 | **全部十课，放在 M3**：试玩指标中的“10 分钟理解、20 分钟改良、30 分钟创造”都依赖教学；M1、M2 不受影响，你可以先玩 |

确认后，我从 M0 和 M1 开始。
