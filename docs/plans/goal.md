# 持续开发目标（Goal）

**日期：2026-10-28**

**用途：** 给每个开发会话一个固定的方向和工作循环。新会话先读 [CLAUDE.md](../../CLAUDE.md)、[PROGRESS.md](../../PROGRESS.md)，再读本文件，然后按第四节循环推进。本文件只定目标和做法，不是规则；规则以 `docs/design/` 最新版本为准，进度以 PROGRESS.md 为准。

## 一、最终目标

交付策划书第十三章的**完整新版 MVP**（Phase 6）：一名可构筑角色，能研究、改良、自创武学，学会四项生活技艺，在一个据点和短路线上持续历练，并让秘籍、技艺、器物和人物关系跨历练留下变化。

路线（主计划 V1.9.1 13.3 节）：

| 阶段 | 要验证的问题 | 状态 |
| --- | --- | --- |
| Phase 1 规则引擎 | 规则能无界面运行，关键算例可手算复现 | 完成 |
| **Phase 2 构筑实验室** | 玩家输掉一场后，愿不愿意改一处武学再打一次 | **进行中：M0、M1 完成** |
| Phase 3 采药医术与人物 | 采药 → 配药／医治 → 改良试剑 → 人物反馈能否形成闭环 | 未开始 |
| Phase 4 完整研究与自创 | 能否合法创造并保存一门自创秘籍，且不能刷研究 | 未开始 |
| Phase 5 采矿锻造 | 第二条生活闭环与真实收支 | 未开始 |
| Phase 6 整合与外部验证 | 完整 MVP 内容齐备，外部玩家可持续游玩 | 未开始 |

每个阶段结束后先评估再进入下一阶段；评估未通过时调整当前切片，不把后面的系统提前堆进来。

## 二、当前目标：完成 Phase 2

**退出条件：** 约 5 位不参与开发的试玩者能在浏览器打开试玩链接，独立玩 30 分钟，并能达到 [Phase 2 方案](phase2-lab-plan.md)第一节的指标（10 分钟理解、20 分钟第一次改良、30 分钟第一次创造、能说出因果与跨轮取舍、失败后提出改造假设再战）。

### M3 十课教学

完成标准：新玩家不看文档也能从第一课走到第一次出门前的状态。

- 先按 V1.9.1 规则逐课走查教学细则第三章，做不到的课写进冲突报告，由负责人决定改配置还是改课；不暗中给玩家加属性。
- 每课一个“按推荐操作能完成”测试和一个“不按推荐也不会卡死”测试；授业只结算一次；未完成的课可免费补做。

### M4 试玩版

完成标准：5 位试玩者可以独立打开并完成 30 分钟流程。

- 首批 6 个公开词缀（敌人细则第九章），并在矩阵中加入词缀维度。
- 键盘完整操作与无障碍检查；水墨风格界面。
- 一键导出试玩记录（决策、结果、改良历史）。
- 发布到同一个试玩链接，附试玩说明与观察表。

## 三、守则

- 规则来源：只用最新策划书及其配套资料的数值；文档没写的口径记入实现说明第四节；缺失或冲突写进冲突报告，请负责人决定，不自行编数。
- 测试：预期值来自文档手算或规则推导，测试名注明出处；不把引擎输出抄成预期。
- 引擎：`src/` 保持纯数据、纯函数、确定性，不依赖 DOM；网页只负责显示和输入。
- 数值：新数值标“首轮提案”或“待验证”；未经模拟或试玩不写“已平衡”。
- 范围：Phase 2 方案第 2.2 节列出的“不做”一律不提前做。界面超时时按价值排序，可把 A／B 对照或词缀后移，但要先说明。

## 四、每个会话的工作循环

1. **对齐**：读 CLAUDE.md、PROGRESS.md、本文件；`git log` 看上次做到哪；`npm run check` 确认基线通过。
2. **选任务**：取第二节中第一个未完成、且没有被阻塞的任务。任务太大就先拆成能在一次提交内完成的小步。
3. **查依据**：找到该任务对应的策划书章节；发现缺口或冲突，先记录并请负责人决定，同时转去做不受影响的任务。
4. **实现**：先写来自文档的测试，再写实现；改网页时用本地浏览器走一遍主要流程并截图核对。
5. **验证**：`npm run check` 全部通过；涉及数值时重跑矩阵并更新报告。
6. **记录**：在 PROGRESS.md 勾掉任务、更新“下一步”、写入新决策；必要时更新实现说明。
7. **提交**：中文提交信息，第一行概括改动；推送前征得负责人同意。
8. **汇报**：用几行说明完成了什么、怎么试、已知问题、需要负责人决定的事。

## 五、必须停下来问负责人的情形

- 规则冲突、范围增减、体验取舍（给出推荐，由负责人拍板）。
- 需要新增或修改策划书数值，或新建策划书版本。
- 推送到远程仓库、更新试玩链接、对外分享。
- 一个里程碑完成，进入下一个里程碑或下一阶段之前。
- 连续两次尝试仍无法让测试按文档预期通过。

## 六、可直接使用的目标提示

新会话或自动循环可以直接使用下面这段：

> 按 `docs/plans/goal.md` 持续推进《武林·自创绝学》。先读 CLAUDE.md、PROGRESS.md 和 goal.md，运行 `npm run check` 确认基线；然后取第二节第一个未完成且未阻塞的任务，按第四节的循环完成一小步：测试预期来自策划文档、实现、`npm run check` 通过、更新 PROGRESS.md、中文提交。遇到第五节的情形就停下，给出推荐并等待负责人决定；推送前先征得同意。
